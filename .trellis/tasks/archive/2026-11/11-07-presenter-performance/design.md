# 性能归因与改动边界

以文稿代数、请求／步骤与窗口身份关联输入、调度、worker 返回、帧发布、GPUI 绘制；计时使用单调时钟，记录汇总数据，不记录用户文稿正文。对被后续输入取代的目标单独计数，避免只统计成功样本而低估连按卡顿。

| 入口 | 记录阶段 | 有证据时的优化方向 |
|---|---|---|
| 打开 | 读盘 → 结构解析 → 原生页元数据 → 映射 → 首张候选光栅 → commit → 显示尺寸光栅／上传 → 首次绘制 | 若回复已就绪而消费者未唤醒，缩短现有通道的交付等待。若元数据主导，先定位逐页加载、标签和几何成本，再评估可等价取得的字段。若首张重复渲染，按实际画面尺寸验证复用。 |
| 翻步 | 输入 → 目标 generation/page/crop → 排队 → 命中层级或光栅 → 纹理准备 → FirstVisible／Settled | 若观众请求被低优先级任务拖住，先减少失效或重复工作。若 GPU 上传前复制主导，先消除相同帧的重复转换。若 tick 中讲者重建主导，局部减少无变化的数据重建。 |

每条路线只在分段结果支持时进入实施，不预设重写调度器、更换 PDF 引擎或取消轮询。保留当前用户配置与字体、几何、rotation、PageLabel、notes mapping、投影公开快照的约定。缓存键必须包含有效代数、页、裁切和目标像素；跨窗口不得假定纹理可共享。方案可单独回退，诊断结果与原始基线独立保存。

`docs/PROJECT_PLAN.md` 中 16.6 ms / 50 ms 是缓存命中时按键到 OS Present 的目标；GPUI paint 不能证明达标。其 800 ms 条目是进程启动到首页，不能作为打开任意 PDF 的承诺。
