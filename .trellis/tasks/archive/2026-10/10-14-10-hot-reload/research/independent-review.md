## Findings (fixed)

1. `crates/ferrostage-platform/src/reload.rs`: `read_stable` read the entire file before checking the final1KiB for EOF. A large incomplete but momentarily stable replacement could therefore repeatedly allocate/read its full contents. It now opens read-only, seeks to the tail, reads at most1024 bytes and checks EOF before full-file reading. The tail handle is closed before the complete read, whose resulting EOF/size and post-close stat are still revalidated. Existing actual watcher regression now also rejects an EOF located only before the final1KiB and accepts a valid short file. No PDF write API was added.

2. `crates/ferrostage-ui/src/shell/reload.rs`: malformed external replacements were reported through the Presenter error banner even though EOF is only a readiness hint. Root clarified the original H-2 zero-error-during-write requirement and synchronized design/spec wording. Structure parse rejection, typed PDFium `Unreadable`/`EmptyDocument`/`InvalidPageGeometry`, and rejected metadata/structure document construction now log debug diagnostics and preserve the old projection without adding a banner. Actual GPU/worker/rollback/retirement errors remain visible. A disconnected structure worker now explicitly reports a runtime failure. The native integration regression covers malformed bytes containing EOF, real PDFium input rejection and inconsistent owned structure/metadata; each retains the complete snapshot and generation without a new error. Typed classification regression ensures library/worker/bitmap/render/generation/rollback faults are not silenced.

3. `shell/reload.rs`: the generic error path after Phase::Commit always attempted Abort, including failure to send rollback after consuming a successful commit, and failure to send Retire after publishing. Abort cannot undo an active generation, and post-publication cleanup must target the old generation. The handler now tracks whether it consumed successful commit authority. Before publication, subsequent rollback-channel failure sets explicit `failed_worker`, suppresses mixed-generation scheduling and records candidate cleanup responsibility. After publication, Retire-send failure retains the new published core/visual and records only the old generation for retirement; neither branch attempts Abort. `worker_disconnect_after_commit_owns_the_correct_generation` uses the existing injected RasterBackend and actual RenderHandle command/reply channel: an intentional backend panic runs after successful Commit but before the coordinator consumes its reply. The test covers both obsolete and publishable cases and asserts immediate settlement, exact snapshot/core generation, render blocking and correct orphan generation. No production fault hook, public API or new dependency was introduced.
