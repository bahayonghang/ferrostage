1. **F1 — Focused controls lose Enter/Space to global actions (confirmed native regression).** `presenter.rs:220–225` uses `on_key_down`, while GPUI `window.rs:5969–5981` dispatches matching key-binding actions and returns when consumed, before raw key listeners. Required regression uses actual focused GPUI key dispatch, verifies one activation/no navigation, and preserves unfocused global navigation and modal behavior. Root assigned this repair.

2. **F2 — Open eligibility differs between button and shortcut (confirmed native/code).** Presenter disables Open while Presenting (`presenter.rs:508`), but `poll_focus` opens a chooser unconditionally for `Intent::Open` (`shell.rs:545`); `begin_import:377` rejects only after a selection. Root's `v4-audience-open-presenter-dialog.json` confirms the chooser appears from Audience. Preserve `import_allowed`: no replacement while Presenting or incompatible window transactions. Confirm the current Presenter is actually active before showing the localized refusal; gate before chooser and again when consuming its result. Required regression: audience-origin Open while Presenting never prompts, keeps session/page/blank unchanged, and targets Presenter feedback. Root assigned this repair.

3. **F3 — Unsafe-topology recovery can retain a fullscreen/stale Presenter (code finding, physical operation NOT_RUN).** `tick:960–965` stops Audience then calls `recover_presenter`; its early return at `847–852` checks only whether the stored MonitorId remains in the topology. It ignores fullscreen mode and whether the old GPUI display mapping remains current. With `presenter_start_fullscreen=true`, Audience loss can leave the surviving Presenter fullscreen, contrary to G7 and parent design §3. Root approved a bounded repair using the existing replacement/confirmation transaction. Validate the strict current mapping and windowed recovery after unsafe topology; keep initial startup-fullscreen behavior distinct, and wait through Unavailable/zero without stale placement or automatic Start. Headless event/coordinator regressions can verify state and handles; they cannot satisfy the physical hotplug gate.

4. **F4 — Jump Backspace is consumed by default Previous binding (code finding).** Default settings bind Backspace to Previous. The Jump editor handles Backspace only in Presenter `on_key_down:292–298`; the same GPUI priority described in F1 consumes Previous first. Shell intentionally discards navigation while a modal exists, so the input is not edited. A button-only activation repair does not address this. Recommended regression: actual Jump→digits→Backspace, including a configured numeric navigation binding, with modal edit priority, no committed audience navigation, and intact Enter/Escape semantics. Reported to Root and implementation owner; review awaits the authorized result.

5. **F5 — Idle navigation emits a raw English core error (code finding; original native trigger unknown).** `shell.rs:333–343` sends Next/Previous/Black/White from Idle to core; `apply:295–296` renders `error.to_string()`. Core returns `NotReady { Idle }`. Root's `v4-resumed-idle.json` shows the same text, but does not prove which key caused it. **Idle Escape is not established as the cause:** `stop:773–775` already guards StopPresentation by Presenting. Stage-invalid intents should give localized feedback or an explicitly chosen harmless rejection; test actual Idle action routes. Do not change core error display merely to localize the UI.

6. **F6 — Closing Jump during Swap/Stop can leave a hidden preview (code finding).** `swap:807–809` and `stop:767–769` set `modal=None` without applying CancelJump. Core StopPresentation only freezes its timer and changes stage (`state.rs:180–183`); it retains the preview. Jump→default S, or an Audience-close/topology Stop while Jump is open, can therefore hide the editor while subsequent Next/Previous still navigate only the preview. Reported to Root for a bounded coordinator fix: when discarding the Jump UI, cancel its preview together; do not alter core Stop's general semantics. Required actual-shell regression checks that closing the modal leaves no preview and that later navigation changes the committed page.
