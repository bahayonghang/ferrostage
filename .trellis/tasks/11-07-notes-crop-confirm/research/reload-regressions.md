# 备注裁切的热重载回归

候选文稿的几何、旋转、公开裁切或独立备注映射变化时，先检查是否涉及备注或已有裁切确认。需要复核的候选停在讲者私有状态；此时旧文稿继续保有自己的代数，观众端没有候选预上传帧。停止放映后仍保留该候选，重新选择方向并确认才进入已有的光栅、上传及可回滚提交。普通无备注文稿在没有裁切历史时仍走自动更新。

- 文档层 `cargo test -p ferrostage-document --lib --locked` 通过 12 项测试。新增用例覆盖普通宽屏、两种候选方向、混合尺寸、正确配对的独立备注。
- 渲染层 `cargo test -p ferrostage-render --lib --locked` 通过 20 项测试。私有样本请求仅向讲者回复像素；模拟第一次光栅失败后，剩余作业取消，可以重试同一页或重新选样本，旧活动文稿仍可继续渲染。样本批次使旧就绪凭据失效，而且不会产生新的提交凭据。
- 裁切候选的解析、文稿构建和待审状态独立于讲者面板尺寸。回归测试在准备期间反复切换备注目标高度 610／611，验证旧工作台布局变化不会阻止新版进入裁切确认。最终候选上传和提交继续要求窗口、文稿、裁切及目标尺寸身份匹配。
- 使用固定 PDFium 和 `cargo test -p ferrostage-ui --features test-support,pdfium --lib shell::reload:: --locked`，受影响的 8 项测试全部通过。新增 `changed_crop_waits_across_stop_before_any_replacement_is_published` 使用现有普通文稿和右侧备注文稿，验证放映中旧代保留、私有候选不进入任何窗口预上传、旧确认不能冒用、停止后选择并应用裁切、提交后仍在 Ready 且没有观众窗。
- 扩展原有两窗提交／回滚测试，检查相同结构重载后保留已确认规则。修正其中一处过时的错误候选断言：源码版本 `f72d33d` 从 Git 归档独立复现，在同一依赖、配置和 DLL 下，原测试 `reload/tests.rs:395` 因播放导航序号从 12 增至 13 而失败。拒绝替换后必须使用新的播放身份来隔离旧的绘制回执，遵循 `.trellis/spec/frontend/pdf-playback.md` 的“Recovery requires a fresh identity”规则。现断言要求序号严格增加，并继续逐字段比较整个剩余快照（包含私有边界、旧公开像素、遮屏、裁切、文稿代数和页）。
