# ADR-009: Isolated GStreamer media playback

Status: accepted for task11 implementation on 2026-10-15. Product/native validation is recorded in the task report, independently of research.

The sole native backend is GStreamer 1.28.8 from the official archives pinned by `packaging/media/runtime.json` (observed core 1.28.8 GIT, selected plugins 1.28.8.1). Rust bindings are exactly gstreamer 0.25.4, gstreamer-app 0.25.2 and gstreamer-video 0.25.2. They are dependencies only of the separate `ferrostage-media-helper` package's `native` feature. Neither the GUI nor the pure media library depends on that package, including under workspace feature unification. Default CI requires no GStreamer SDK. No second backend, unsafe product code, child HWND, new license/advisory waiver or complete wheel redistribution is permitted.

The selected closure contains 47 executable/DLL files and 18 plugins. Build/distribution staging verifies exact archives and individual entry hashes before extracting only selected entries. Full original licenses, source recipes, source URLs and patent notices accompany the closure. Runtime checks require the selected filenames but do not pin installed DLL hashes: users retain the right to replace LGPL libraries with compatible versions. Windows/VC system imports are prerequisites, not bundled files.

The pure GUI library handles animations with image 0.25.10 (GIF/WebP features), selection, identity and supervision. A background supervisor serializes one active decoder/audio owner, with latest-value command and frame slots. The native helper receives a bounded binary protocol over pipes; header and geometry validation precede payload allocation. Commands, stdout and stderr are drained away from the UI thread. Stop immediately invalidates the accepted identity; prior child exit or kill/reap precedes creating another. No UI join is used. Missing/partial runtime or decoder failure affects only the media slot and leaves the PDF available.

Only the first public autostart slot is selected in document order. Clicking another slot stops the old owner; Presenter exposes explicit controls and progress. Ready never starts media. Page/generation/blank/Stop/Close invalidate media; unblank does not resurrect the prior decoder. A process-wide checked monotonically increasing playback identity survives Controller replacement. AudienceMediaFrame.slot_id is this opaque public instance identity, not the PDF annotation index; controller source/annotation/epoch envelopes never enter Audience.

Media frames are packed BGRA8. Both windows clone the same core BgraFrame allocation and account images in their existing window TextureCache, including swap headroom. Public frame geometry is prepared on the background worker: contain within the original physical annotation aspect using transparent letterbox, then conservatively crop the public intersection (ceil left/top, floor right/bottom). The canvas is bounded before allocation. PDF then media then ink/laser preserves composition. Notes-only annotations cannot create an audio owner.

Schema remains v1; media.max_decode_height defaults to1080, accepts1..2160 and applies to the next instance, with width always at most1920. Existing unknown-key preservation and future-version read-only policy remain. User media/PDF files are read-only; embedded payloads use unique create-new owned temporary directories removed after playback retirement.
